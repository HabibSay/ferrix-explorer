# Partie 2 — Moteur de Quick Look / Preview & Compression (architecture dédiée)

Principe directeur : **pour chaque type de fichier, choisir la bibliothèque la plus rapide disponible en licence permissive par défaut**, avec une **architecture pluggable** permettant d'ajouter des moteurs plus rapides mais à licence restrictive (comme LZTurbo) **en option, jamais par défaut**, pour rester 100% open-source "out of the box".

### Nouveau crate : `fx-preview`

```
fx-preview/
├── traits.rs          # trait PreviewProvider { fn render(&self, path) -> PreviewContent }
├── images/            # décodage images
├── documents/         # PDF, Office (via Shell handlers en fallback)
├── media/             # vidéo/audio
├── text/              # code source, coloration syntaxique
├── archives/          # listing + extraction rapide
└── backends/          # moteurs de (dé)compression pluggables
```

### Table des moteurs par type (défaut OSS vs option "Turbo")

| Type de contenu | Moteur par défaut (OSS, inclus) | Licence | Moteur "Turbo" optionnel (perf max, opt-in) |
|---|---|---|---|
| **Images** (JPEG/PNG/WebP/AVIF) | `zune-image` (pur Rust, SIMD) | MIT/Apache | `turbojpeg` (bindings libjpeg-turbo) pour JPEG pur débit max |
| **Images RAW** (photo) | `rawloader` (pur Rust) | MIT/Apache | `libraw` (LGPL) si l'utilisateur l'active |
| **Redimensionnement/thumbnails** | `fast_image_resize` (SIMD Rust) | MIT/Apache | — |
| **Archives ZIP/Deflate** | `libdeflater` (bindings `libdeflate`) — bien plus rapide que zlib classique | MIT | **LZTurbo** (powturbo) — plugin externe, non bundlé, opt-in explicite |
| **Archives 7z** | `sevenz-rust` (pur Rust) | MIT/Apache | SDK 7-Zip natif en fallback |
| **Archives RAR** (lecture seule) | `unrar` (bindings unrar.dll) | ⚠️ Propriétaire, nécessaire pour compatibilité | — |
| **Compression interne app** (cache, transferts) | `zstd` (bindings officiels Facebook, mode long-range) | BSD | **LZTurbo** opt-in si installé par l'utilisateur |
| **PDF** | `pdfium-render` (moteur Google Pdfium) | BSD | — (évite `mupdf` qui est AGPL, incompatible avec distribution permissive) |
| **Vidéo** (thumbnail/preview) | **Windows Media Foundation** natif (via `windows-rs`) — gratuit, zéro dépendance licence | Système | `ffmpeg` en option (LGPL/GPL selon build) pour formats exotiques |
| **Audio** (waveform/lecture) | `symphonia` (pur Rust) | MPL-2.0 | — |
| **Texte/Code** (coloration syntaxique) | `tree-sitter` (incrémental, très rapide) | MIT | `syntect` en fallback (grammaires Sublime, plus lourd) |
| **Polices** | **DirectWrite** natif (via `windows-rs`) | Système | — |
| **Office (docx/xlsx)** | Shell Preview Handlers natifs Windows (fallback simple) | Système | Parsing custom en v2 si besoin |

### Architecture pluggable (trait Rust)

```rust
pub trait CompressionBackend: Send + Sync {
    fn decompress(&self, input: &[u8]) -> Result<Vec<u8>>;
    fn compress(&self, input: &[u8], level: u8) -> Result<Vec<u8>>;
    fn name(&self) -> &'static str;
}

// Enregistrement au runtime, sélection auto du plus rapide dispo
pub struct BackendRegistry {
    backends: Vec<Box<dyn CompressionBackend>>,
}
```

**Important — point légal/licence** : LZTurbo (powturbo) n'est **pas en licence OSI-approuvée** (gratuit non-commercial, source disponible mais restrictions). Il sera donc :
- **jamais inclus dans le build par défaut** distribué publiquement,
- proposé comme **plugin externe optionnel** que l'utilisateur compile/installe lui-même s'il accepte la licence,
- clairement documenté dans `docs/LEGAL.md` et dans les paramètres ("moteur de performance externe — licence tierce").

Cette même logique "défaut OSS + plugin perf opt-in" s'applique à tout moteur tiers non-permissif qu'on voudrait ajouter plus tard (ex: `mupdf`, `ffmpeg` full build).

# Partie 3 — PRD Complet Mis à Jour

## 1. Vision produit

> Un explorateur de fichiers natif Windows 10/11, écrit 100% en Rust, qui égale ou dépasse `explorer.exe` en fonctionnalités, tout en étant radicalement plus rapide (démarrage instantané, scroll sans lag, recherche instantanée façon "Everything", aperçu instantané façon Quick Look macOS), 100% open-source (MIT/Apache-2.0), avec une architecture extensible par plugins.

**Nom de projet proposé :** `ferrix-explorer`

## 2. Objectifs & Non-objectifs

### Objectifs
- Navigation fluide, listes virtualisées, zéro lag sur dossiers massifs
- Menu contextuel natif Windows complet
- Recherche globale instantanée (USN Journal)
- Multi-onglets, multi-fenêtres, mode dual-pane commander
- Quick Look (aperçu instantané, toutes formats courants)
- Sidebar complète (épinglés, récents, drives, cloud)
- Intégration cloud (OneDrive/GDrive/Dropbox) via Cloud Files API Windows
- Palette de commandes, terminal intégré, CLI compagnon
- Accessibilité complète dès le départ (UI Automation)
- Architecture plugins (WASM) pour extensibilité communautaire

### Non-objectifs (v1)
- Remplacement du process `explorer.exe` (app standalone + option "défaut")
- Support Linux/macOS natif (architecture modulaire, mais focus Win10/11)
- Recherche sémantique/IA — **hors scope, non prévu**
- Éditeur avancé intégré (on s'appuie sur handlers existants + Quick Look)

## 3. Stack technique

| Composant | Choix |
|---|---|
| Langage | Rust (edition 2021/2024) |
| UI | Slint (plan B : iced, ou Win32+Direct2D si limitations) |
| Shell interop | `windows-rs` (IShellFolder, IContextMenu, IFileOperation, CfApi) |
| Parcours FS | `jwalk` + `rayon` |
| Watch FS | `notify` |
| Indexation/recherche | `tantivy` + lecture USN Journal/MFT |
| DB locale | `rusqlite` (métadonnées, config, tags, historique) |
| Preview engine | `fx-preview` (cf. Partie 2) |
| Compression | `zstd`, `libdeflater`, `sevenz-rust` (+ plugin LZTurbo opt-in) |
| Terminal intégré | ConPTY via `windows-rs` |
| Async | `tokio` |
| Cloud APIs | `reqwest` + `oauth2`, Microsoft Graph API, Google Drive API v3, Dropbox API |
| Config | `serde` + TOML |
| Logging | `tracing` |
| Plugins | WASM runtime (`wasmtime`) — v2 |
| Packaging | `cargo-wix` (MSI) / MSIX |
| CI/CD | GitHub Actions (windows-latest) |

## 7. Risques techniques

| Risque | Mitigation |
|---|---|
| Interop COM Shell complexe via `windows-rs` | Temps dédié Tranche 3, s'inspirer de projets existants (ex: `Files` C#/WinUI) pour la logique, réécrire en Rust |
| USN Journal nécessite privilèges admin parfois | Fallback `jwalk` classique si accès refusé |
| Maturité Slint pour UI complexe | Plan B : `iced` ou Win32+Direct2D |
| CfApi (Cloud Files) peu documentée en Rust | Wrapper manuel `windows-rs`, tests sur machine avec OneDrive réel |
| **Licence LZTurbo incompatible OSS** | Jamais bundlé par défaut — plugin externe opt-in uniquement, disclaimer `docs/LEGAL.md` |
| Licence `unrar` (propriétaire) | Isolé dans `fx-codec`, désactivable à la compilation, clairement documenté |
| UI Automation complexe à implémenter correctement | Démarrer tôt (Tranche 0-1), tester avec Narrator Windows réellement, pas juste "cocher la case" |

## 8. Conventions de développement

- Tests unitaires `fx-core`/`fx-index`/`fx-preview`/`fx-codec` ; tests d'intégration manuels documentés pour `fx-shell`
- CI : build + clippy + fmt obligatoires
- Conventional commits (`feat:`, `fix:`, `perf:`, `a11y:`, `docs:`)
- Chaque crate documentée (README + rustdoc)
- Licence : MIT OU Apache-2.0 (dual license)
- `docs/LEGAL.md` obligatoire listant toute dépendance à licence non-permissive et son statut (optionnelle/isolée/opt-in)
